# 预测视觉跟随与论文对应关系

当前任务是保持距离跟随无人机。距离变小时，同样的横向相对速度会产生更大的视线角速度（约为 `v_perp / range`）；单纯增大偏航增益不能消除这个几何问题。因此本实现同时预测视线、抑制横向视线变化、保留转向和制动空间。

## 参考方法与接口适配

1. Yang 等，*High-Speed Interception Multicopter Control by Image-Based Visual Servoing*，
   [DOI: 10.1109/TCST.2024.3451293](https://doi.org/10.1109/TCST.2024.3451293)，
   [公开预印本](https://arxiv.org/abs/2404.08296)。第 IV 节、算法 2 的核心是先在图像曝光时刻校正，再传播到当前时刻。
   本工程用曝光时刻的 `PoseHistory` 补偿相机运动，六维位置/速度滤波器保留在最后观测时刻，查询时外推副本。自身姿态和惯性估计由 PX4 EKF 提供；没有重做论文包含 IMU 偏置的完整延迟 EKF，也不接收目标机遥测。
2. Hu 等，*Precise Interception Flight Targets by Image-Based Visual Servoing of Multicopter*，
   [DOI: 10.1109/TIE.2025.3559951](https://doi.org/10.1109/TIE.2025.3559951)，
   [公开预印本](https://arxiv.org/abs/2409.17497)。第 III-A 节采用比例导航降低视线角速度，第 III-B 节区分图像水平居中和机体倾斜造成的视场变化。
   本工程在闭合阶段加入有界 PNG 横向修正，并用预测视线和连续偏航参考保留目标视场。输出仍是 PX4 速度/偏航设定值，没有替换姿态内环为论文的推力/SO(3) 控制器。

这些是面向现有 PX4 跟随接口的工程适配，不是两篇论文的逐公式完整复现；论文的稳定性证明不能直接套用于此实现。

## 当前算法

`r` 为相机到目标的相对位置，`v_r` 为目标与相机的相对速度，`u = r / ||r||`。

- 连续完整观测估计目标位置、速度，以及经过低通和幅值约束的加速度。单目深度受机体姿态影响，因此加速度只用于垂直于视线的短时预瞄；深度滤波保持恒速度模型，避免框宽抖动被外推成前后冲刺。
- 预测 `r_future = r + v_r * tau + 0.5 * a_perp * tau²`。偏航窗口最多 0.4 s，并随速度不确定度和观测中断减小。预测方位相对当前方位的超前量限定在 ±0.45 rad，混合权重为 0.8，再通过原有偏航速度/角加速度平滑器。
- 闭合阶段计算 `omega_LOS = (r × v_r) / ||r||²`，采用 `a_PNG = N * v_close * (omega_LOS × u)` 的横向修正，`N = 2`。将其转换为有界的短时速度增量，交给统一的加速度/jerk 平滑器；已到跟随间距或正在退让时不使用拦截闭合项。
- 静止跟随间距设为 6 m；横向相对速度过大时，转向所需间距增加到 `min(10 m, |v_perp| / 0.35 rad/s)`。额外考虑停车距离。总向前速度（包含目标速度前馈）按 `v * 0.40 + v² / (2 * 2.5) <= 可用水平距离` 约束；0.40 s 为响应时间、2.5 m/s² 为制动减速度参数，防止旧的目标速度估计抵消制动。它约束的是平滑器前的速度参考，不代表实际飞机瞬时速度必然满足该式。
- 近距离退让速度最多 2.8 m/s，沿当前视线反向退让，同时保留横向速度匹配。速度指令仍按 3 m/s²、6 m/s³ 连续变化，电机软化不变。
- 视场余量使用检测框边缘，不只看框中心。截断框必须能关联到已有预测目标；只更新与观测射线垂直的两个约束，不能初始化距离，也不把被截掉的框宽用于测距。
- 首次锁定要求置信度 0.55。已有锁定目标的检测若与预测图像位置相差小于 0.18（归一化图像坐标），可使用最低 0.35 的观测；仍需通过滤波创新门限。低分检测不能单独建立新目标。
- 小目标检测使用最近曝光时刻的位置与图像速度预测 ROI，将局部图像放大后送入同一 YOLO 模型，检测框映射回完整相机坐标。每 5 帧重新检测全图；ROI 漏检、无法关联或触碰人为裁剪边界时立即回退全图，超过 0.6 s 未更新则丢弃 ROI。真实相机边缘的截断框仍交由方位更新处理。此项改善远距识别连续性，不改变相机内参或深度计算尺度，也不需要重新训练模型。
- 稳定的相机处理延迟不视为漏帧。新鲜度门限包含最后有效帧的处理延迟；曝光年龄超过 0.85 s、检测器停滞或预测不确定度过大时仍进入制动和重搜。

主要代码为 `px4_fly_control/px4_fly_control/visual_tracking.py`、`safe_visual_follow.py`，配置为 `config/drone_follow.yaml`。

## 验证

先启动双机仿真和一个 YOLO 检测节点；不要同时运行其他键盘或跟随节点。加载 ROS 环境后运行：

```bash
source /opt/ros/humble/setup.bash
source install/local_setup.bash
PYTHONNOUSERSITE=1 python3 scripts/verify_drone_follow.py --fast --output runtime/predictive_fast
PYTHONNOUSERSITE=1 python3 scripts/verify_drone_follow.py --lateral --output runtime/predictive_lateral
```

两个命令应各自使用冷启动的仿真。脚本会操控两架仿真飞机并在结束时请求降落；Gazebo 真值仅用于测试记录和退出条件，不传入跟随控制器。`--lateral` 包含靠近相机、横向移动、反向和停止，避免只验证匀速直线工况。
